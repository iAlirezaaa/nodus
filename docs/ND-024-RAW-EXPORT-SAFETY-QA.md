# ND-024 — guarded raw-recovery JSON export (optional Pages edition)

**Recorded:** 2026-11-18 UTC. **Status:** In progress on branch only; publication **Blocked**, not Verified or Released. **Branch:** `fix/nd-024-startup-storage-recovery`.

## Problem / user-visible change

The standalone local-first Pages recovery dialog offers **1. Download raw data / ۱. دانلود نسخهٔ خام** before any Import or Start fresh. When preparing that download, an exception during DOM insertion or the download link click previously left an allocated object URL, and sometimes a temporary anchor, without cleanup. More importantly, the message falsely said the raw backup had been *downloaded*, even though the browser cannot confirm that it was saved. The exception path must never imply that raw recovery was safely exported or authorize Import/Reset.

The existing `downloadRecovery()` now retains its dated `nodus-recovery-raw-YYYY-MM-DD.json` filename, conservative JSON-integrity validation, and explicit recovery consent; it removes the temporary anchor and revokes an allocated URL on failed synchronous operations. Delayed revocation is guarded against browser exceptions. Success states only **“Raw recovery file prepared for saving; keep it safe.” / “نسخهٔ خام برای ذخیره آماده است؛ آن را در جای امن نگه دارید.”** A synchronous failed attempt leaves `backupTaken=false`, Import/Reset disabled, and the original graph, Undo state, raw IndexedDB record and file references unchanged. No schema, server, authentication, user-data or animation write path was changed. This does **not** prove the file reached the user's disk; the existing user confirmation warning remains necessary before destructive actions.
