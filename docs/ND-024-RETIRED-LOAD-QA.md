# ND-024 — Retired IndexedDB read guard (branch-only)

Date: 2026-11-18. Status **In progress / source slice verified / original Sites release Blocked**.

## Problem and scope

In the optional static Pages edition, `load()` accepted a valid document or missing key after a readonly transaction without verifying that its `db` handle was still current. A synthetic concurrent versionchange/replacement immediately after transaction completion demonstrated that its old result could clear a conflict and overwrite the read baseline. This is a **reproducible state-machine interleaving**, not evidence of observed production data loss or a demonstrated real-browser timing. Original authenticated Site unaffected.

## Acceptance and implementation

- Keep the same connection for the whole readonly IndexedDB transaction, then reject if retired/replaced before returning data or blank.
- No clearing of `localConflict` or `storedBaseline` on a stale result; no document, draft, history, media, import, schema or server persistence change.
- Ordinary valid/missing-key reads still work and can recover with a fresh connection.
- Verify source-exact red/green tests, full Node, project TypeScript, build, existing 4173 Chromium multi-tab, FA/EN, keyboard and mobile flows.

Source: `pages/index.html` one guarded `load()` path and embedded script CSP; tests: `tests/pages-read-transaction.test.mjs`.
