## Bug and bounded change

The optional static Pages app's existing sidebar **Export JSON / پشتیبان JSON** called JSON serialization, Blob creation, URL allocation and anchor click without exception handling. A denied operation could throw without a helpful notification; the previous success toast claimed “Backup downloaded” even though JS cannot prove that the user completed a disk save. Export is particularly important after a failed write or cross-tab conflict, while the unsaved document is only in memory.

The same export control now attempts to prepare the full *current* workspace JSON (after existing editor flush). A successful picker trigger reports **“Backup prepared for saving” / “فایل پشتیبان آمادهٔ ذخیره است”**, not confirmation that the browser/user completed a download. A serialization, Blob, object URL, DOM insertion or click failure is caught, any allocated URL is revoked and a localized retry notification appears; cleanup failures do not hide the original problem. Existing filename and delayed URL revocation are maintained. The separate recovery-quarantine raw export is unchanged. No change to any document, in-session Undo/Redo, IndexedDB, room/server data, authentication, migration, background animation or keyboard shortcut from the export error path. The inline CSP SHA-256 was recalculated from the exact new script, old hash independently checked, new hash `0WSzj0iYIX8hfiAa+4TRDlcDM2hY95iSChy8zT0qAvA=`.
