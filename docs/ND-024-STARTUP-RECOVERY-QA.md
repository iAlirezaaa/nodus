## Reproduced code hazard and change

Before: `load()` used `value ? validate(value) : blank()`; false, null, zero and an absent IndexedDB record all appeared as an empty workspace. For a truthy invalid value, `init()` caught validation failure and loaded `blank()` without blocking `mutate()/queueSave()`. A subsequent edit could overwrite the original raw record in `nodus-pages-v1` / `workspace` / `main` without giving the user recovery options.

Now the absence sentinel is **only** `undefined`; invalid stored values raise `CorruptWorkspaceError` carrying the raw in-memory Structured Clone record (unchanged). On startup the application enters `storageRecovery`, shows a bilingual FA/EN `alertdialog` and pauses edits, Undo/Redo and queued writes. The dialog offers raw JSON export first; import or new workspace remains disabled until export is triggered. New workspace additionally requires an explicit confirmation. If JSON encoding fails (e.g. circular data), both destructive choices remain disabled. Restore/import commits via IndexedDB **before** unlocking; a failed transaction keeps the previous raw data and recovery lock, while success clears the fake-blank Undo history and focuses the canvas.

No network transfer, database migration, altered key, D1/R2 operation, audience change or automatic delete was added. Local graph and remote authenticated Site remain separate.
